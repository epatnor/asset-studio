# Azshara Island prototype

Azshara Studio ("Human vision. AI craft.") is an AI-driven indie game project.
Long-term goal: a stylized fantasy MMO with its own art style that runs on old
integrated Intel graphics. WoW 1.12 is the reference for how lightweight an
MMO can be (it ran well on very modest hardware), not for the art style.
This prototype is a small single-player test to decide whether Godot is good
enough as engine. The engine choice is NOT final.

## The game

A small island in the sea, stylized semi-low-poly look.

- A few medieval houses in a forest, a path between them, lanterns along the path
- Start zone, one point of interest, one goal
- Grass, stones, low cliff ledges that break up the landscape
- A spring in the middle feeding a stream down to the sea, reeds along its banks
- Animated grass, trees, bushes (wind), animated water (sea and stream)

### Zones (design plan, 2026-10-12)

Two islands. The main island goes from lush (east, start) to autumn (west,
facing the dark island). Both islands rise towards the channel between them
and meet it in cliffs. An ancient stone bridge, a relic of the old kingdom,
crosses the channel high above the sea; some of its stones have broken and
fallen into the water. Torches will go on the bridge.

1. Start half: lush and safe. Rich green grass, flower patches, cosy leafy
   trees, sunlight filtering through the canopy onto the path (light shafts).
   The village, start zone and stream live here.
2. Middle: an autumn transition. Autumn leaves on the ground and in the
   trees, warm orange, red and ochre colours.
3. The dark island, west of the main island across a channel: gloomy and
   dangerous. Lore: it was once the seat of the kingdom, until a dark force
   corrupted it. Ruined monuments and buildings of the old royal seat, dead
   trees, bushes, stones, ground fog in the lowlands, a restless stormy sky
   gathering over it. The magical portal (the goal) is here.
   The palette is near monochrome black and grey (dark ground, dark sand,
   dark rock). Colour comes only from light sources: torches, glowing
   mushrooms, magic and fire.

Planned (2026-10-12): the world will be rebuilt with more biomes, named
after Valheim's as a shorthand: meadows (the main island today),
ashlands-like (the dark island), mountain (snow), plains (open land with
our autumn theme) and, most important, a dark forest of pines and spruces.
See PLAN.md.

Zones are driven by one zone value: 0 at the main island's east end, about
0.6 at its west end, 1 on the dark island, softened by noise, so terrain colour, scattering,
trees, sky, fog and light all blend between zones from the same source.

## Art direction

- Our own stylized look, not a copy of any other game.
- Low contrast, hue shifts with value (dark cooler and more saturated, light
  warmer), analogous colour patches at equal value, calm areas of rest (70/30).
- Material transitions are soft and organic: wide blend bands broken up by
  soft multi-scale noise, height-based blending from texture height maps
  mixed with a crossfade, and an earthy fringe where materials meet.
- Textures are procedural and tileable, generated by scripts in the repo.
- Check values in the greyscale screenshots, and judge from the player's eye
  height (the beach views), not only from above.

## Tools

- Godot 4.7, Compatibility renderer (OpenGL 3.3), flatpak:
  `flatpak run org.godotengine.Godot`
- Blender 5.2, flatpak: `flatpak run org.blender.Blender`
- Blender objects are built by saved Python scripts in the repo, exported as GLB:
  `flatpak run org.blender.Blender -b -P "$PWD/tools/blender/build_x.py"`
  The Blender flatpak runs in another working directory, so script paths must
  be absolute.
- Procedural textures are numpy scripts run with Blender's bundled Python
  (the host Python has no numpy):
  `flatpak run org.blender.Blender -b -P "$PWD/tools/textures/build_ground_textures.py"`
- No ad-hoc click-modeling. Blender MCP is only for inspecting and rendering previews.
- Prefer open-source tools. No local AI inference on this machine.
- Always ask before generating an image with an AI model.

## Invariants

- Target hardware: Intel HD 4600 (i5-4590T). Compatibility renderer only.
- If it builds the world, do it in Godot code: terrain, sea, stream,
  scattering, shaders.
- If it stands in the world, do it in Blender: houses, lanterns, cliff rocks,
  tree trunks.
- Everything is placeholder-procedural first. Pipeline GLBs from 3DAI Studio
  replace placeholders later, one category at a time.
- Grass, stones and reeds use MultiMeshInstance3D with random rotation and scale.
- Wind and water animation live in shaders, never in geometry.

## Terrain

- Composed heightmap in layers, not raw noise:
  - radial island falloff with a slightly perturbed coastline
  - low-frequency rolling hills (few octaves, low gain, domain warping)
  - masked terrace steps for low ledges
  - stream channel carved from the spring to the sea
  - smooth flattened plots for houses
- Regular grid, per-cell diagonal chosen by slope (no zigzag), smooth normals
  from the heightmap.
- Cliff faces are NOT heightmap geometry. The terrain gets a soft step and
  separate rock meshes are placed along ledge edges.
- The generator is a `@tool` script with exported parameters, tunable with
  sliders in the editor.
- Automated checks:
  - stream height decreases monotonically to the sea
  - walkable slopes stay under a max angle
  - island border is below sea level

## Reference notes

- `docs/foliage_notes.md`: how vegetation is scattered, ideas from Godot
  foliage tools, and pitfalls (vertex colours, sRGB, glTF V flip).
- `patriks_input/`: inspiration images from Patrik. `docs/visual_references.md`
  summarises what to take from them. Read both before visual work.

- `docs/shore_and_water_notes.md`: techniques for coastlines, shore waves,
  swash and wet sand, with sources and pitfalls. Read it before changing the
  beach, the sea or the stream.

## Visual verification loop

A screenshot script renders fixed camera angles (top-down, low angle over hills,
along the stream) to PNG. After every visual change, look at the images and
compare them with the previous ones.

## Working rules

- Before launching the game for Patrik, stop any running instance
  (`pkill -f "godot-bi[n] --path"`; the bracket keeps pkill from matching
  its own shell when chained with the launch), so only one game window is open.

- Chat with the user in Swedish. All code, comments and filenames in English.
- Filename comment at the top of every file.
- Block comments above code, never inline. No decorative divider lines.
- One step at a time, one command at a time. Wait for feedback.
- Commit to local git after each step the user approves. Local git is the
  source of truth; no GitHub for now.
